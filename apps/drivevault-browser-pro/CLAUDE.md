# DriveVault Browser Pro - rules (adds to the repository root file)

A Chrome-like web browser for Windows: C++20, Qt 6.8 / Qt Quick, **Qt WebEngine (Chromium)**. Version 0.4.0 = Phases 1 - 4 of `docs/Browser-Pro-Plan.md` (the browser shell, the ad blocker engine, hiding / scriptlets / stand-ins, the defence against pages that detect ad blockers). **No installer, no Release, not in the Master Pro catalog yet** (Phase 6). Read the plan first; do not label a planned feature as available.
Owner's decisions (2026-11-19): Qt WebEngine for this program (the suite rule "no WebView" does not apply to it, as for Master Pro's browser tab); **no Google sign-in, no Google sync** (plan section 13); extensions are on hold (Qt 6.10.3 crashes in `setExtensionEnabled`, `docs/Phase0b-Results.md`).

## Layout
```
src/core/   no WebEngine, tested: UrlUtil (address bar rules, safe / unique file names), BookmarkStore (JSON + Netscape HTML import / export), HistoryStore (JSON lines, 20,000 max), BrowserSettings (JSON, zoom per host)
src/adblock/ no WebEngine, tested (tst_adblock, tst_cosmetic): NetRule, FilterParser (one line of a list -> network / cosmetic / comment / unsupported / site switch), RuleSet (host index + word index + fallback; immutable, thread safe), Cosmetic (parseCosmetic, CosmeticStore: hide / style / scriptlet rules by domain, exceptions, generic names), StandIns (the harmless replacement files and the table of known ad libraries), PageScript (the script of one page), ListManager (list files, async parse, on / off mask, the Update download)
resources/adblock-page.js   the script that runs INSIDE pages (scriptlets, hiding), written for this program; qml/BrowserWindow.qml puts it into the view before each navigation (`onNavigationRequested` -> `prepareScripts`)
src/app/    BrowserApp (the QML singleton "Browser": stores, downloads, shared profile, helpers), DownloadModel (WebEngine downloads), AdBlockInterceptor (the engine's request filter, network thread), AdBlockController (QML: Browser.adblock), main.cpp, app.rc
qml/        Main (keeps the windows alive), BrowserWindow (tabs, address bar, bookmarks bar, pages, find, permissions, menus, shortcuts, --selftest), NewTabPage, SidePanel (history / bookmarks / downloads / settings), Theme, Tr (Thai + English), LineIcon, IconButton, BButton
tests/      tst_core (unit tests), tst_smoke (starts the real exe: picture, local page, panels, private window, the window's own checks)
spike/      phase0b = the throw-away Qt 6.10 test of the plan (not built by the project)
```
Output `build\release\bin\DriveVaultBrowserPro.exe`. Data: `%LOCALAPPDATA%\DriveVault\BrowserPro` (`--data-dir <dir>` for tests: also keeps downloads in `<dir>\downloads`).

## Commands (from this folder)
```powershell
.\scripts\build.ps1 -Test        # configure + build Release + tst_core + tst_smoke (smoke opens real windows for about a minute)
..\..\scripts\run-browser-pro.bat   # smoke start / look at the program (no install)
.\scripts\make-icon.ps1          # redraws resources\icons\app.png / app.ico
```
Diagnostics of the exe: `--screenshot <png> [--size WxH] [--lang th|en] [--panel history|bookmarks|downloads|settings] [--private]`, `--selftest <json> <page address>` (17 checks of tabs, pin, bookmarks, history, suggestions, find, zoom, typed address, panels; exit 0 = all passed), `--data-dir`, `--lang`, addresses as arguments.

## Rules
- **Defence against ad block detection (0.4.0, plan section 4; results and open points: `docs/anti-adblock-results.md`)**: switch `antiDetectEnabled` (default on, independent of the cosmetic switch; it works with NO list installed: `ListManager::pageScriptFor(lib, url, cosmetic, defend)`, config key `def`). In `adblock-page.js`: (1) with the defence on, generic `.class` / `#id` rules hide ELEMENT BY ELEMENT with an inline style and **never hide an empty box** (no child element, no text): a bait box is empty, so the page never sees it hidden; a box that gets content later is looked at again (mutation on its parent); with the defence off the old per-name style rule is used (this is also the control of the lab); (2) the names `FuckAdBlock` / `BlockAdBlock` / `SniffAdBlock` and the instances `fuckAdBlock` ... are defined by us as always-"not detected" objects whose setters ignore the page; (3) wall hider: an element (up to 8 ancestors up) that is `position: fixed`, or absolute / sticky with z-index >= 100, covers at least 50 % x 30 % of the window and whose text matches the words for "ad blocker" (English and Thai) is hidden, its backdrop sibling too, and `html, body` get `overflow: auto; position: static; filter: none` (the queue works a few hundred nodes per round). Interceptor side: stand-ins also answer `fetch` / XHR to the known ad addresses (type Xhr), a blocked picture is answered by the 1x1 gif, `fuckadblock.js` / `blockadblock.js` get a stand-in. The defence is only claimed for what `tst_lab anAdBlockerDetectorFindsNothing` shows (each detector with the defence on AND off, plus false-positive controls); never write "bypasses every site" anywhere, and when you add a detector to the lab keep its OFF control. Real websites are not tested.
- **Inside the page (0.3.0, plan section 3.1 layers 2 - 4)**: `AdBlockController::scriptFor(url)` -> `ListManager::pageScriptFor` -> `buildPageScript(library, PageCosmetics, generic names)`; QML sets it as a `userScripts` entry (DocumentCreation, MainWorld, main frame only) in `onNavigationRequested`, so it runs before any script of the page (proved in `tst_lab` with Chromium). It adds NOTHING to the page's global scope; hiding uses a constructable style sheet (`adoptedStyleSheets`: no `<style>` element, not stopped by the page's CSP), 40 selectors per rule with a one-by-one fallback (one bad selector kills a whole CSS rule). The ~50,000 generic `.class` / `#id` rules are NOT turned into CSS: the page script scans the DOM (and watches mutations) and gives a rule only to names that occur (`[class~="x"]` / `[id="x"]`). Specific rules, `#@#` exceptions, `$generichide` / `$elemhide` (site switches kept in two small `RuleSet`s; `$elemhide` keeps the scriptlets) are applied in C++. **Scriptlets are written fresh for this program** (never copy code of uBlock Origin: GPLv3): set-constant, abort-on-property-read / -write, abort-current-script, abort-on-stack-trace, no-xhr-if, no-fetch-if, no-setTimeout-if, no-setInterval-if, adjust-setTimeout / -setInterval, prevent-addEventListener, json-prune, remove-attr, remove-class, set-local-storage-item, set-session-storage-item, set-cookie (+ -reload), cookie-remover, no-window-open-if, nowebrtc, with the short names the lists use (`aopr`, `acs`, `aeld` ...); a scriptlet name not in `aliasTable` makes the line Unsupported. Cookie / storage values are limited to a safe list. **Stand-ins** (`StandIns.cpp`, served as `dvres:/<name>` by `StandInHandler`; the scheme is registered BEFORE `QtWebEngineQuick::initialize()` with `CorsEnabled` and `ContentSecurityPolicyIgnored`): `$redirect=<name>` and a table of known libraries (adsbygoogle, analytics, gtm, gpt, fbevents, ads.js-style bait names) answer a blocked script with a file that defines what the page expects; a stand-in never calls out (tested). A `||host/path` rule does not match an address that has a port (ABP semantics): lab rules use `/path`. Not done: procedural selectors (`:has-text`, `:-abp-*`, `:xpath` ... counted as unsupported), hiding / scriptlets inside iframes, `remove-node-text`, `json-edit`, HTML filtering `##^`.
- **Ad blocker (0.2.0, plan section 3)**: `AdBlockInterceptor` (one object made in `main.cpp` BEFORE the profile, set on the shared profile; a private window attaches it through `Browser.adblock.attach(privateProfile)`) asks `ListManager::match` for every http(s) request that is not the page itself (a navigation is never blocked) and calls `info.block(true)`. Everything the parser calls Unsupported (regular expressions, `$removeparam`, `$csp`, `$popup`, unknown options, procedural selectors, unknown scriptlets) is counted but not applied - the Settings page says so; never half-apply a filter you do not understand. Lists are files `<data>\filters\<id>.txt` (+ `.meta.json`) or, when missing there, `<exe folder>\filters\<id>.txt` (the installer snapshot, Phase 6); `ListManager::defaultCatalog` names the official addresses. **Nothing is downloaded unless the user presses "Update filter lists"** (diagnostic `--update-lists <json>` does the same and exists only for the owner-approved test download into `.tools\browser-test-data`; never run it without the owner's go-ahead) (`ListManager::update`: https only, 60 MB at most, must look like a filter list, written atomically, SHA-256 in the meta file); the program ships no list yet. The rule set is swapped as one immutable object (`std::atomic<std::shared_ptr>`): the network thread never locks it. The registrable domain used for `$third-party` is an approximation (last two labels, three after co / ac / com ... under a two-letter code), not the public suffix list. Speed on a SYNTHETIC list of 150,000 rules: loaded in 0.4 s, 6 us per request (`tst_adblock aBigListLoadsAndMatchesFast` prints it); on the REAL lists (EasyList, EasyPrivacy, Fanboy Social and Annoyance, downloaded 2026-11-19: 111,416 network rules active, 49,868 + 56,688 + 657 + 4,203, plus 83,000+ cosmetic lines and about 3,200 unsupported lines that are counted, not applied) it loaded in 0.32 s and took 15.5 us per request (opt-in `DV_TEST_FILTER_DATA=<data dir> tst_adblock realListsLoadAndMatch`). `tst_smoke theAdBlockerStopsRequestsInTheRealEngine` proves with Chromium that a blocked request never reaches a local server (normal and private window) and that pause per site, the master switch and a list switch let it through. Diagnostic: `--probe <json> <page address>`.
- **Honest labels**: Settings says what the ad blocker does NOT do yet. Never show a switch that does nothing. Cookies are NOT cleared by "Clear history and cache" (the Quick profile has no cookie store API); the page says so.
- Private window: its own `WebEngineProfile { offTheRecord: true }`, declared LAST in `BrowserWindow.qml` (Qt destroys children in creation order; the profile must go after every view). It never writes history, session or zoom. Downloads and bookmarks made in it are kept (the page says so).
- The shared profile is made in `main.cpp` on the stack **before** the QML engine so it outlives it. Never write `profile: profile` in a view. `QQuickWebEngineProfile` has no constructor with a name: use `setStorageName`.
- Notifications are refused without asking by default (`blockNotifications`); every other permission asks (`WebEnginePermission`, remembered on disk, the bar under the toolbar). The program never opens a downloaded file; risky extensions (exe, msi, bat, ps1, js, lnk ...) get a warning (`riskyFileName`).
- The user agent drops `QtWebEngine/x` and says `Windows NT 10.0` (the engine said 6.2). This is how Chrome-based browsers present themselves; it is not a promise that every site accepts it.
- Texts: every string is in `qml/Tr.qml` (English + Thai together). QML gotchas as in Master Pro: ids are per file, a delegate with `required` properties has no `model` object, `font.family` takes one name.
- Network: nothing is downloaded by the program itself; pages load what they load. Search uses the engine the user chose (DuckDuckGo default).
- Not done yet (do not claim): tab drag-to-reorder, tests of the defence on real websites (only lab pages so far), a shipped filter list (needs the owner's go-ahead; the lists of the owner-approved test download are only in `.tools\browser-test-data`), lists for scriptlets / anti-adblock (uBlock filters, Adblock Warning Removal: not chosen, not downloaded), tests on real websites, Picture-in-Picture and video download (Phase 5), import from Chrome, print to a printer (only "save as PDF"), clearing cookies, extensions, the installer and the Master Pro card. H.264 / AAC video does not play with the Qt binaries (no proprietary codecs, plan section 12).
