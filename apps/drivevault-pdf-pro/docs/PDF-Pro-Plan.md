## 1. เป้าหมายและขอบเขต

โปรแกรม Windows แบบ native (C++20, Qt 6.8 / Qt Quick, CMake เหมือนโปรแกรมอื่นในชุด ไม่ใช้ Electron / Tauri / WebView) ที่ **ทำงานในเครื่อง ไม่อัปโหลดไฟล์ไปที่ไหน**

### ความสามารถที่อยู่ในขอบเขต
1. เปิดไฟล์ PDF แบบ Acrobat
2. รวม / แยก PDF ตามลำดับที่ต้องการ
3. บีบอัด PDF ลดขนาดไฟล์และเพิ่มประสิทธิภาพไปพร้อมกัน เพื่อคุณภาพสูงสุดของ PDF
4. เพิ่มข้อความ รูปภาพ รูปร่างต่างๆ และสิ่งอื่นที่ทำได้ (ดู 3.4)
5. ส่งออก PDF เป็นรูปภาพ (หลายรูปรวมเป็นไฟล์ ZIP)
6. ป้องกัน PDF (ใส่รหัสผ่าน) / ปลดล็อก PDF (**เฉพาะเมื่อมีรหัสผ่าน**)
7. ปิดบังข้อความ: **ลบเนื้อหาออกจากไฟล์จริง และวางกล่องดำทับตำแหน่งนั้น**
8. อื่นๆ ที่คุ้มและทำได้จริง (ดู 3.8)

### ตัดออกจากขอบเขต (ตัดสินใจแล้ว)
- **ส่งออก PDF เป็น Word / PowerPoint / Excel และแปลง Word / PowerPoint / Excel เป็น PDF** (ผู้ใช้ตัดออก ทำให้ไม่ต้องพึ่ง Office/LibreOffice และตัดความเสี่ยงเรื่องเค้าโครงเพี้ยนออกทั้งหมด)
- แก้ไข "ข้อความเดิม" ที่อยู่ใน PDF แบบโปรแกรมประมวลผลคำ (ทำได้ไม่ดีกับ PDF โดยธรรมชาติ ดู 3.4)
- ถอดรหัสผ่านด้วยการเดา/brute force (ไม่ทำ ดู 3.6)
- แปลง HTML เป็น PDF (ต้องใช้เอนจินเว็บ ขัดกฎ "ไม่ใช้ WebView")
- ลายเซ็นดิจิทัล (PAdES/ใบรับรอง), OCR, เปรียบเทียบไฟล์, PDF/A, สแกนจากสแกนเนอร์ (เก็บไว้เป็นความคิดสำหรับอนาคต ไม่อยู่ในแผนนี้)
- คลาวด์ บัญชีผู้ใช้ การทำงานร่วมกันออนไลน์

จุดต่างจากเว็บอย่าง iLovePDF: ไม่ต้องอัปโหลด (เอกสารลับอยู่ในเครื่อง), ไม่จำกัดขนาด/จำนวนไฟล์, ใช้ออฟไลน์ได้, มีตัวอ่านกับเครื่องมือในโปรแกรมเดียว

## 3. รายละเอียดฟีเจอร์

### 3.1 เปิดไฟล์แบบ Acrobat (ข้อ 1)
- โหมดแสดง: หน้าเดี่ยว, ต่อเนื่อง, สองหน้า; พอดีความกว้าง/พอดีหน้า/ซูมกำหนดเอง; หมุนมุมมอง; เต็มจอ
- แผงด้านข้าง: thumbnail, สารบัญ (bookmark), รายการ annotation
- ค้นหาทั้งเอกสาร (ไฮไลต์ผล, ไปผลถัดไป), เลือก/คัดลอกข้อความ (ภาษาไทยต้องถูกต้อง), ลิงก์ในเอกสารใช้งานได้
- แท็บหลายไฟล์, จำหน้าและการซูมที่อ่านล่าสุด, รายการไฟล์ล่าสุด, ลากไฟล์มาวางเพื่อเปิด
- พิมพ์ (ผ่านตัวพิมพ์ของ Windows), โหมดมืด (กลับสีเฉพาะมุมมอง ไม่แก้ไฟล์)
- ไฟล์ที่มีรหัส: ถามรหัสตอนเปิด ไม่บันทึกรหัสลงดิสก์
- ไฟล์ใหญ่: เรนเดอร์ทีละหน้า แคชภาพ มีเพดานหน่วยความจำ งานเรนเดอร์อยู่นอก UI thread

### 3.2 รวม / แยก (ข้อ 2)
- รวม: ลากไฟล์มาเรียงลำดับ เลือกช่วงหน้าของแต่ละไฟล์ ลบ/หมุนหน้าก่อนรวมได้ ดูตัวอย่างลำดับหน้า (thumbnail) ก่อนสร้างไฟล์
- แยก: ตามช่วงหน้า (เช่น 1-3,5,8-), ทุก N หน้า, ตาม bookmark ระดับบน, ตามขนาดไฟล์สูงสุด; ตั้งชื่อไฟล์ผลลัพธ์ตามแบบ
- จัดหน้าในไฟล์เดียว: ลากเรียงใหม่, หมุน, ลบ, แทรกหน้าว่าง/หน้าจากไฟล์อื่น, ตัดขอบ (crop)
- คงสิ่งที่ควรคงไว้: bookmark ที่ยังชี้หน้าถูก, ลิงก์ภายใน, ฟอร์ม (ตามที่เอนจินรองรับ) หากข้อใดไม่คงไว้ ต้องแจ้งผู้ใช้ก่อนบันทึก

### 3.3 บีบอัดและเพิ่มประสิทธิภาพ (ข้อ 3)
ขั้นตอนเป็นชั้น เรียงจากปลอดภัยไปแรง ผู้ใช้เลือกระดับ (ต่ำ/กลาง/สูง/กำหนดเอง):
1. เขียนโครงสร้างใหม่ + object streams + deflate สูงสุด (ไม่เปลี่ยนคุณภาพ)
2. ลบ object ที่ไม่มีใครอ้างถึง, metadata/thumbnail/ข้อมูล editor ที่ไม่จำเป็น
3. ฟอนต์: รวม/ตัดส่วนที่ไม่ใช้ เฉพาะที่ทำได้โดยไม่เสียตัวอักษร
4. ภาพ: ลด DPI ตามเป้า (เช่น 150/110/72), แปลงเป็น JPEG ตามคุณภาพที่เลือก, ข้ามภาพที่เล็กอยู่แล้ว, **ไม่ทำให้ภาพ/ไฟล์ใหญ่ขึ้น** (ถ้าผลใหญ่กว่าเดิมให้เก็บของเดิม)
5. linearize (เปิดบนเว็บเร็ว)
- "คุณภาพสูงสุด" ในที่นี้หมายถึง ลดขนาดโดยรักษาความคมของข้อความ/เส้น (ไม่ rasterize ข้อความ) และให้ผู้ใช้คุมคุณภาพภาพเอง **ไม่เคลมโดยไม่วัด**
- แสดงผลเป็นตัวเลขจริง ก่อน/หลัง (ขนาด, % ที่ลด, จำนวนภาพที่ถูกลดคุณภาพ) และ preview เทียบหน้าตัวอย่างก่อนบันทึก

### 3.4 เพิ่มข้อความ รูปภาพ รูปร่าง และอื่นๆ (ข้อ 4)
ทำกับ **สิ่งที่ผู้ใช้เพิ่มเอง** (อยู่ใน model ของโปรแกรม แก้ขนาด ฟอนต์ สี ตำแหน่ง ลำดับชั้นได้ ลบ/ย้ายได้ undo/redo ได้):
- ข้อความ (กล่องข้อความ: ฟอนต์ ขนาด สี ตัวหนา/เอียง จัดแนว), รูปภาพ (PNG/JPEG วางแล้วย่อ/ขยาย/หมุน), รูปร่าง (สี่เหลี่ยม วงรี เส้น ลูกศร หลายเหลี่ยม สี เส้นขอบ ความหนา ความโปร่งใส)
- ที่ทำได้เพิ่มเติม: ปากกา/วาดเขียนอิสระ, ไฮไลต์/ขีดเส้นใต้/ขีดฆ่า, คอมเมนต์ (sticky note), ตราประทับ (stamp), ลายน้ำ (ข้อความ/รูป ทั้งเอกสาร), เลขหน้า/header/footer, กรอกฟอร์ม AcroForm, ลายเซ็นแบบภาพ (วาด/พิมพ์/รูป)
- การเก็บ: เลือกได้ว่าเก็บเป็น annotation (แก้ภายหลังได้) หรือ flatten (ยุบเป็นเนื้อหาหน้า ถาวร)
- **ไม่ทำ:** แก้ "ข้อความเดิม" ที่อยู่ในเอกสารแบบโปรแกรมประมวลผลคำ เพราะ PDF เก็บตัวอักษรที่วางตำแหน่งแล้ว ไม่ได้เก็บย่อหน้า ถ้าต้องการเปลี่ยนข้อความเดิม แนะนำให้ใช้ปิดบัง (3.7) แล้วเพิ่มข้อความใหม่ทับ
- **ภาษาไทยเป็นจุดเสี่ยงหลัก:** เพิ่มข้อความไทยต้อง shaping (สระ/วรรณยุกต์ซ้อน) แล้วเขียนตำแหน่งตัวอักษรเอง พร้อมให้ข้อความยังค้นหา/คัดลอกเป็นไทยที่ถูกต้อง ต้องมีเทสต์ทั้งภาพและเทสต์ดึงข้อความกลับ ไม่ใช่เช็คแค่ว่าไฟล์เปิดได้
- ฟอนต์: ใช้ Inter / Noto Sans Thai ที่โปรแกรมมี + ฟอนต์ในเครื่อง ผู้ใช้ต้องมีสิทธิ์ฝังฟอนต์นั้น แสดงคำเตือนถ้าฟอนต์ห้ามฝัง

### 3.5 ส่งออกเป็นรูปภาพ (ข้อ 5)
- เลือกหน้า (ทั้งหมด/ช่วง/หน้าเดียว), รูปแบบ PNG หรือ JPEG (คุณภาพกำหนดได้), DPI (72–600), พื้นหลังโปร่งใสเมื่อ PNG (ถ้าต้องการ)
- **หน้าเดียว** → บันทึกเป็นไฟล์รูป; **หลายหน้า** → รวมเป็นไฟล์ `.zip` ไฟล์เดียว (ชื่อไฟล์ในซิป `ชื่อเอกสาร-0001.png` ...) ผู้ใช้เลือกได้ว่าจะให้ซิปหรือโฟลเดอร์รูป
- การทำ ZIP: เขียน ZIP เอง (แบบ store/deflate ผ่าน miniz หรือโค้ดเขียนเอง) ไม่ต้องพึ่งโปรแกรมอื่น เรนเดอร์ทีละหน้าและเขียนลง ZIP ทันที เพื่อไม่กินหน่วยความจำมากเมื่อหลายร้อยหน้า มี progress และยกเลิกได้
- เทสต์: ตรวจจำนวนไฟล์ในซิป ขนาดภาพตาม DPI และเนื้อหาพิกเซลของหน้าเทียบการเรนเดอร์ปกติ

### 3.6 ป้องกัน / ปลดล็อก (ข้อ 6)
- **ป้องกัน:** รหัสเปิดไฟล์ + รหัสเจ้าของ + จำกัดสิทธิ์ (พิมพ์/คัดลอก/แก้ไข/แก้ annotation) ด้วย AES-256 ผ่านเอนจิน (qpdf) แสดงคำเตือนว่าโปรแกรมอ่าน PDF บางตัวอาจไม่เคารพสิทธิ์ที่จำกัด
- **ปลดล็อก:** **ต้องใส่รหัสผ่านที่ถูกต้องเท่านั้น** แล้วบันทึกเป็นไฟล์ที่ไม่มีรหัส/ไม่มีข้อจำกัด มีข้อความให้ผู้ใช้ยืนยันว่ามีสิทธิ์ในไฟล์นั้น
- **ไม่มี** การเดารหัสผ่าน, พจนานุกรม, brute force ใดๆ และไม่ข้ามรหัสเปิดไฟล์
- รหัสผ่านไม่ถูกเขียนลงล็อกหรือไฟล์ตั้งค่า ไม่ค้างในหน่วยความจำนานเกินจำเป็น
- ต้องตัดสินใจ: ไฟล์ที่ "เปิดอ่านได้โดยไม่ต้องใส่รหัส แต่จำกัดสิทธิ์ด้วยรหัสเจ้าของ" จะให้ลบข้อจำกัดได้หรือไม่เมื่อไม่ได้ใส่รหัสเจ้าของ (ตามความตั้งใจ "เฉพาะมีรหัสผ่าน" แผนนี้ **ไม่ลบ** จนกว่าผู้ใช้ใส่รหัสเจ้าของที่ถูกต้อง)

### 3.7 ปิดบังข้อความ (ข้อ 7) ตามที่กำหนด: ลบเนื้อหาจริง และวางกล่องดำทับ
สำคัญที่สุดเรื่องความถูกต้อง: การวางกล่องดำทับอย่างเดียว **ไม่ใช่การปิดบัง** เพราะข้อความยังอยู่ในไฟล์ ดังนั้นต้องทำสองอย่างพร้อมกัน:
1. **ลบเนื้อหาออกจากไฟล์จริง:** ลบตัวอักษรที่อยู่ในพื้นที่ที่เลือกออกจาก content stream; ภาพที่ทับพื้นที่ → เขียนพิกเซลใหม่เฉพาะส่วนนั้น (rasterize เฉพาะบริเวณ) หรือตัดภาพ; ลบ annotation/ข้อความที่ซ่อน/ไฟล์แนบ/ thumbnail/metadata ที่มีเนื้อหาเดียวกัน; เขียนไฟล์ใหม่ทั้งไฟล์ (ไม่เก็บ incremental update เดิมที่ยังมีข้อมูลเก่า)
2. **วางกล่องดำทับตำแหน่งเดิม** เป็นเนื้อหาหน้า (ไม่ใช่ annotation ที่ลบทิ้งได้)
- วิธีเลือก: ลากกรอบ, เลือกจากข้อความที่ค้นหา, รูปแบบ regex พร้อม preset (เลขบัตรประชาชนไทย 13 หลัก, เบอร์โทร, อีเมล, เลขบัญชี) → แสดงรายการ/ทำเครื่องหมายก่อน (ยังไม่ลบ) → ตรวจ → "ใช้ redaction"
- ตัวเลือก: สีกล่อง (ค่าเริ่มต้นดำ), ข้อความทับในกล่อง (เช่น "REDACTED") ไม่บังคับ
- **ตรวจสอบหลังทำ (บังคับ):** ดึงข้อความของไฟล์ผลลัพธ์แล้วต้องไม่พบข้อความที่ลบ, ตรวจ metadata/ไฟล์แนบ, เรนเดอร์หน้าแล้วพื้นที่เป็นสีกล่อง ถ้าตรวจไม่ผ่านต้องไม่บันทึกและแจ้งผู้ใช้ มีเทสต์อัตโนมัติเรื่องนี้เป็นเกณฑ์ผ่าน/ไม่ผ่านของเฟส 6
- ข้อควรเตือนผู้ใช้: ย้อนกลับไม่ได้หลังบันทึก (บันทึกเป็นไฟล์ใหม่เสมอ ไม่ทับไฟล์ต้นฉบับ)

### 3.8 ฟีเจอร์อื่นๆ ("ฯลฯ") ที่เสนอเข้าแผน (ทำถูก ใช้บ่อย ต่อยอดจากข้างบนได้เลย)
- แก้ metadata (ชื่อเรื่อง ผู้เขียน คีย์เวิร์ด), ดู/ลบไฟล์แนบ, ล้างข้อมูลส่วนตัวก่อนส่งไฟล์
- ซ่อม PDF ที่เสียเล็กน้อยด้วยการสร้างโครงสร้างใหม่ (ผ่านเอนจิน)
- งานเป็นชุด (batch) บนโฟลเดอร์: บีบอัด / ใส่ลายน้ำ / ใส่รหัส มีรายงานผลต่อไฟล์
- ลำดับก่อนหลังตามความคุ้ม: metadata/ล้างข้อมูล → batch → ซ่อมไฟล์
- ความคิดสำหรับอนาคต (นอกแผน): OCR ภาษาไทย/อังกฤษ, เปรียบเทียบไฟล์, ลายเซ็นดิจิทัล, สแกนจากสแกนเนอร์

## 4. สถาปัตยกรรมและเทคโนโลยี

### 4.1 หลักการ
- แยกเป็นไลบรารี static ต่อโฟลเดอร์ แบบ Video Editor (`core`, `pdfengine`, `document`, `render`, `edit`, `tools`, `export`, `security`, `app`, `ui`) ทิศทางพึ่งพาลงล่างเท่านั้น
- `pdfengine` เป็นชั้นเดียวที่แตะไลบรารี PDF ภายนอก เพื่อสลับตัวและเขียนเทสต์ได้
- งานหนักทั้งหมดนอก UI thread มี progress และยกเลิกได้
- **ไม่แก้ไฟล์ต้นฉบับ:** บันทึกเป็นไฟล์ใหม่ หรือเขียนไฟล์ชั่วคราวแล้วแทนที่แบบ atomic (มี `fileutils::writeAtomic` อยู่แล้ว) มี autosave/กู้คืน
- ทุกการแก้ไข undo/redo ได้
- ข้อความทุกอย่างใช้ `qsTr` + แปลไทย; ใช้ `AppText` และกฎ `ThaiMetrics` เหมือน Video Editor (ไทย/อังกฤษขนาดและระยะบรรทัดเท่ากัน)
- โปรแกรมออฟไลน์ 100% ไม่มีฟีเจอร์ที่ต้องดาวน์โหลดอะไรเพิ่ม (ไม่มี OCR/โมเดลในแผนนี้)

## 7. ชุดทดสอบ (แนวทาง ตามกฎของโปรเจกต์: ใช้ข้อมูลจริง วัดผลจริง)
- ไฟล์ทดสอบสร้างเองในเทสต์ (ข้อความไทย/อังกฤษ, ภาพ, ฟอร์ม, ไฟล์มีรหัส, ไฟล์ใหญ่หลายร้อยหน้า) ไม่พึ่งไฟล์ลิขสิทธิ์ภายนอก
- ตรวจผลเป็นข้อมูล: จำนวนหน้า, ข้อความที่ดึงกลับ, ขนาดไฟล์ก่อน/หลัง, พิกเซลของหน้าที่เรนเดอร์ (เทียบเกณฑ์), `qpdf --check`, เนื้อหา ZIP
- เทสต์ความปลอดภัยของ redaction เป็นเกณฑ์บังคับ (3.7)
- เทสต์ UI offscreen แบบเดียวกับ `tst_ui_flow` (ล้มทันทีเมื่อมีคำเตือน QML) และเทสต์ประสิทธิภาพเปิดไฟล์ใหญ่
- ทุกเทสต์ต้องเงียบ (`DV_NO_AUDIO=1`) และไม่แตะไฟล์/ข้อมูลของผู้ใช้
- ไม่ทดสอบตัวติดตั้ง/ถอนติดตั้งโดย agent ตามกฎข้อ 3a

## 9. สิ่งที่ต้องให้เจ้าของตัดสินใจก่อนเริ่ม Phase 0

1. **เอนจินอ่าน/เรนเดอร์:** PDFium (แนะนำ) หรือ Qt PDF (ถ้าผ่านเกตสัญญาอนุญาต)
2. **ขอบเขตรุ่นแรก:** ออกรุ่นแรกหลังเฟส 3 (อ่าน + รวม/แยก + บีบอัด) หรือรอจนครบเฟส 6
3. **ปลดล็อก:** ยืนยันว่า "เฉพาะมีรหัสผ่าน" รวมถึงรหัสเจ้าของด้วย (ไฟล์ที่แค่ห้ามพิมพ์/คัดลอกแต่เปิดได้ จะไม่ถูกลบข้อจำกัดถ้าไม่ใส่รหัสเจ้าของ)
4. **การส่งออกรูป:** ค่าเริ่มต้นเมื่อหลายหน้า = ZIP (ตามที่ขอ) ผู้ใช้เลือกโฟลเดอร์แทนได้ ยืนยันหรือไม่
5. **ตั้งเป็นโปรแกรมเปิด .pdf ของ Windows:** ให้ผู้ใช้เลือกเอง (แนะนำ) หรือเสนอตอนติดตั้ง
6. **ฟีเจอร์ "อื่นๆ" (3.8):** อยากได้อะไรเพิ่มจากรายการ (metadata/ล้างข้อมูล, batch, ซ่อมไฟล์) หรือมีอย่างอื่นในใจ
7. **ชื่อและสี:** ใช้ "DriveVault PDF Pro" และสีแดง `#EF4444` ตามที่มีใน Master Pro อยู่แล้ว (ยืนยัน)

## 10. ขั้นต่อไปที่แนะนำ
ถ้าเจ้าของอนุมัติ: เริ่ม Phase 0 ด้วยการตรวจสัญญาอนุญาต PDFium / qpdf / Qt PDF จากไฟล์ LICENSE จริงของเวอร์ชันที่จะใช้ ขอสิทธิ์ดาวน์โหลดเครื่องมือก่อนตามกฎ ("ดาวน์โหลดอะไร จากที่ไหน ขนาดเท่าไร") แล้วทำต้นแบบเปิด PDF 10 ไฟล์เพื่อวัดความเร็ว/หน่วยความจำและกำหนดเป้าหมายตัวเลขของ Phase 1
