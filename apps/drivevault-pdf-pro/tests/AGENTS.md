# drivevault-pdf-pro/tests - rules (adds to the parent files)

| Suite | What it covers |
|---|---|
| `tst_pdfengine` | open, page sizes, rendering measured on pixels, clamping, cancel, text extraction, 600 pages, several threads at once, encrypted file (needs `.tools\qpdf`, skipped without it) |
| `tst_controller` | `DocumentController`: open / close, document ids, error codes, recent files (order, unique, limit, persisted), language |
| `tst_ui_flow` | the real QML UI offscreen with real mouse clicks: open, pages, zoom, thumbnails, language, close, recent, password dialog, invalid file; fails on any QML warning |

- Test PDFs are generated by `TestPdf.h` (Helvetica text, no sample files); measure results (pixels, extracted text, page counts), do not only check return values. Add a test with every feature or bug fix.
- Run: `.\scripts\build.ps1 -Test`, or `ctest --test-dir build\release --output-on-failure` after `. shared\scripts\env.ps1`. Qt Test output is lost when stdout is redirected: use `-o file,txt`.
- Tests must be silent (`DV_NO_AUDIO=1`, set by CMake), use `QTemporaryDir` and never touch the user's files or settings. The UI test needs `QT_QPA_PLATFORM=offscreen` and `QT_QUICK_BACKEND=software` (set by CMake).
