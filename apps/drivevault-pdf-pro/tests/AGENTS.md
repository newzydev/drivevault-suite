# drivevault-pdf-pro/tests - rules (adds to the parent files)

| Suite | What it covers |
|---|---|
| `tst_pdfengine` | open, page sizes, rendering measured on pixels, clamping, cancel, rotation, text extraction, search (hits and places), character index and text rectangles, outline, links, annotations, Thai text, 600 pages, several threads at once, encrypted file (needs `.tools\qpdf`, skipped without it) |
| `tst_controller` | `DocumentController`: tabs, error codes, remembered view and rotation, recent files, language, dark pages, search (steps, highlights, rotation), selection and copy (also across pages), outline / links / annotations, link safety (`openUri`), page ranges, printing to a file |
| `tst_ui_flow` | the real QML UI offscreen with real mouse clicks, drags and keys: open, pages, zoom, side panel, tabs, bookmarks and comments, search bar, selecting and Ctrl+C, links and the web address question, two page view, rotate, dark pages (pixels), print dialog, remembered view, full screen, password dialog, invalid file, organizer (select, delete, undo, drag, rotate, save, replace question, discard question), split dialog, compress dialog (levels, run, before / after, save, replace question), edit bar (draw, select, move, undo, Delete key, type text, save, unsaved-edits question); fails on any QML warning |
| `tst_pdftools` | qpdf writer: merge order, reorder / delete / duplicate, rotation, crop, blank pages, link cleaning, protected sources, errors, no overwrite, progress / cancel, 600 page merge, split plans, split by size |
| `tst_compress` | `compressFile`: photo reduced (size, pixels before / after, text still text, `qpdf --check`), lossless photo to JPEG, drawings keep their edges, never bigger, small pictures left alone, cancel, protected file stays protected, fast web view; the `Compressor` object (preview copy, save only on request, never over the original) |
| `tst_editor` | `tools/Overlay` on rendered pixels: shapes where they are, rotated page, Thai and English text (shaped, exact text back), bold, pictures, transparency, turning, watermark + page numbers on many pages, protected files, errors, cancel, `qpdf --check`; the `EditorModel` object: draw, select, move, resize, undo, hit areas, marks, save only on request |
| `tst_organizer` | `PageListModel` (select, move, undo, add files, passwords, save checked by reopening and `qpdf --check`) and the controller split API (preview, modes, unique names, cancel leaves no files) |
| `tst_perf` | 500 / 3000 page files, first page time, search time, memory (prints `PERF ...`; loose limits) |

- Test PDFs are generated by `TestPdf.h` (`make` = text pages, `makeFeatureDoc` = outline + links + comment + highlight); Thai text is written with `QPdfWriter`. No sample files; measure results (pixels, extracted text, page counts), do not only check return values. Add a test with every feature or bug fix.
- Each `tst_ui_flow` test that needs a known start calls `fresh(path, name)` (closes every tab, forgets the remembered views, opens the file) so a failing test cannot break the next ones.
- Run: `.\scripts\build.ps1 -Test`, or `ctest --test-dir build\release --output-on-failure` after `. shared\scripts\env.ps1`. Qt Test output is lost when stdout is redirected: use `-o file,txt`.
- Tests must be silent (`DV_NO_AUDIO=1`, set by CMake), use `QTemporaryDir` and never touch the user's files or settings; printing tests write a PDF file (`outputFile`), never to a real printer. The UI test needs `QT_QPA_PLATFORM=offscreen` and `QT_QUICK_BACKEND=software` (set by CMake).
