# drivevault-pdf-pro/src - rules (adds to the parent files)

- `pdftools` (library `dp_pdftools`) is the only place that includes qpdf headers: `writePages(list of PageSpec, outFile)` builds a new file (source pages are shallow copied, sources are never modified, output goes to `<out>.part.tmp` then is renamed, no overwrite unless asked), `planSplitBySize` measures real files; `SplitPlan` has the split rules and file names. Warnings are codes (`bookmarks`, `forms`, `encrypted`, `linksRemoved:n`, `cropTooBig:n`) translated by `Tr.warning`. Every qpdf call stays in the worker thread of the caller. Test with `tests/tst_pdftools.cpp`.
- `PageListModel` is the QML singleton `Organizer` (the organizer list with undo; registered in `main.cpp` and in `tst_ui_flow`). Added files are registered with the controller (`registerExtra`) so the image provider can draw their thumbnails.
- `pdfengine` (library `dp_pdfengine`) is the only place that includes PDFium headers or calls `FPDF_*`. Everything above works with `PdfDocument`, `QImage`, `QString`, `QRectF`. New engine features (merge, compress ...) are added there with a test in `tests/tst_pdfengine.cpp`.
- `PdfDocument` is thread safe because every method locks `pdfiumMutex()`; do not hold that lock while calling back into Qt code that may re-enter it. Pages are 0-based in C++ and QML. Positions are **points of the page as shown** (top left origin, view rotation applied): the engine converts from / to PDF space (`toShown` / `toPage` at 1/16 point resolution) - never convert elsewhere.
- `DocumentController` is the QML singleton `Doc` (module `DriveVault.PdfPro.Backend`, registered by `main.cpp`). It owns the tabs (each: document, view rotation, remembered view), the search results, the selection, the annotation list and the print job. Keep its values simple (strings, ints, lists, maps); return error codes as strings (`password`, `format`, `file`, `tooLarge`, `unknown`; print: `noDocument`, `badRange`, `busy`) - the texts live in `Tr.qml`. Search, annotation loading and printing run on the thread pool and report back with queued calls; state that belongs to a tab is dropped when the tab changes (`resetPerDocumentState`).
- The image provider URL is `image://pdf/<tabId>/<page>/<pixels per point * 1000>/<rotation 0..3>/<dark 0|1>`; the tab id is unique for the run so an old request can never draw the wrong document.
- Settings live in `<dataDir>\settings.ini` (language, dark pages, recent files, a remembered view per file keyed by a hash of its path, at most 100); `--data-dir` overrides the folder (tests use it). No other persistence. A link opens only `http`, `https` or `mailto` (`openUri`), and only after the user said yes in `LinkDialog`.
- Every new `.qml` file must be listed in `src/ui/CMakeLists.txt`; singletons also in `set_source_files_properties(... QT_QML_SINGLETON_TYPE TRUE)`. Never give a QML type the name of a Qt Quick / Controls type (`TabBar`, `Icon`, `TextMetrics` ...), and never a property the base type already has (`icon`, `text`, `font` on a Button): the build fails or the Qt type is used silently.
- UI texts: `Tr.s("key")` with both languages in `Tr.qml` (no `qsTr`); always `AppText` (not `Text`) so Thai and English have the same line height; icons are drawn by `LineIcon` (no icon font). Keep `objectName`s stable - `tst_ui_flow` uses them (`homeOpen`, `tab_<n>`, `tabClose_<n>`, `toolbarOpen`, `toggleSidebar`, `sidePanel`, `sideThumbs`, `sideOutline`, `sideComments`, `outline_<n>`, `comment_<n>`, `pageField`, `nextPage`, `prevPage`, `zoomIn`, `zoomOut`, `zoomLabel`, `fitWidth`, `fitPage`, `viewMode`, `rotate`, `darkPages`, `findButton`, `printButton`, `searchBar`, `searchField`, `searchCount`, `searchNext`, `searchPrev`, `searchCase`, `searchClose`, `linkUri`, `linkCancel`, `printDialog`, `printStart`, `printCancel`, `printRangeField`, `printError`, `langTh`, `langEn`, `passwordField`, `noticeBanner`, `recent_<n>`, `pageImage_<n>`, `pages`, `thumbnails`, `organizeButton`, `splitButton`, `homeMerge`, `organizerDialog`, `orgPage_<n>`, `orgDelete`, `orgUndo`, `orgSave`, `orgClose`, `orgResult`, `orgReplaceYes`, `orgDiscardYes`, `splitDialog`, `splitRangeField`, `splitStart`, `splitDone`).
- `tst_ui_flow` fails on any QML warning: run it after UI changes and fix every warning.
