# drivevault-pdf-pro/src - rules (adds to the parent files)

- `pdftools` (library `dp_pdftools`) is the only place that includes qpdf headers: `writePages(list of PageSpec, outFile)` builds a new file (source pages are shallow copied, sources are never modified, output goes to `<out>.part.tmp` then is renamed, no overwrite unless asked), `planSplitBySize` measures real files; `SplitPlan` has the split rules and file names. Warnings are codes (`bookmarks`, `forms`, `encrypted`, `linksRemoved:n`, `cropTooBig:n`) translated by `Tr.warning`. Every qpdf call stays in the worker thread of the caller. Test with `tests/tst_pdftools.cpp`.
- `pdftools/Forms` reads and fills AcroForm fields with qpdf (radio buttons arrive as one entry per button: group by name; appearance streams are generated so PDFium draws them). `PdfDocument` runs a PDFium form fill environment, because `FPDF_RenderPageBitmap` does not draw form fields; keep `FPDF_FFLDraw` after the page render. `FormFiller` is the QML singleton `Forms`. EditorModel autosaves to `<data dir>/recovery/<sha1 of path>.json` and offers it again on open. Test with `tests/tst_forms.cpp`.
- `pdftools/Overlay` paints `EditItem`s (text as outlines + an invisible text layer with a ToUnicode font, pictures, shapes ...) with one painter for the screen (`renderOverlay`, QML image provider `ovl`) and for the PDF (`saveWithEdits`: one QPdfWriter overlay, placed with qpdf on each page, rotation of the page handled). `EditorModel` is the QML singleton `Editor` (items + marks per tab, undo, hit testing, save in the background); positions are points of the page as shown at view rotation 0. A QList copy shares data: take the undo snapshot BEFORE you get a pointer into the list. Test with `tests/tst_editor.cpp`.
- `pdftools/Compress` (`compressFile`) rewrites one file: structure always, images optionally (resolution measured from the content streams, JPEG via Qt). It never writes a file that is not smaller (`written=false`). `Compressor` (src/app) is the QML singleton `Compressor`: it works on a temporary file, registers the result as an extra document for the before / after comparison and saves only on request (never over the original). Test with `tests/tst_compress.cpp`.
- `PageListModel` is the QML singleton `Organizer` (the organizer list with undo; registered in `main.cpp` and in `tst_ui_flow`). Added files are registered with the controller (`registerExtra`) so the image provider can draw their thumbnails.
- `pdfengine` (library `dp_pdfengine`) is the only place that includes PDFium headers or calls `FPDF_*`. Everything above works with `PdfDocument`, `QImage`, `QString`, `QRectF`. New engine features (merge, compress ...) are added there with a test in `tests/tst_pdfengine.cpp`.
- `PdfDocument` is thread safe because every method locks `pdfiumMutex()`; do not hold that lock while calling back into Qt code that may re-enter it. Pages are 0-based in C++ and QML. Positions are **points of the page as shown** (top left origin, view rotation applied): the engine converts from / to PDF space (`toShown` / `toPage` at 1/16 point resolution) - never convert elsewhere.
- `DocumentController` is the QML singleton `Doc` (module `DriveVault.PdfPro.Backend`, registered by `main.cpp`). It owns the tabs (each: document, view rotation, remembered view), the search results, the selection, the annotation list and the print job. Keep its values simple (strings, ints, lists, maps); return error codes as strings (`password`, `format`, `file`, `tooLarge`, `unknown`; print: `noDocument`, `badRange`, `busy`) - the texts live in `Tr.qml`. Search, annotation loading and printing run on the thread pool and report back with queued calls; state that belongs to a tab is dropped when the tab changes (`resetPerDocumentState`).
- The image provider URL is `image://pdf/<tabId>/<page>/<pixels per point * 1000>/<rotation 0..3>/<dark 0|1>`; the tab id is unique for the run so an old request can never draw the wrong document.
- Settings live in `<dataDir>\settings.ini` (language, dark pages, recent files, window geometry and maximized state, a remembered view per file keyed by a hash of its path, at most 100); `--data-dir` overrides the folder (tests use it). No other persistence. A link opens only `http`, `https` or `mailto` (`openUri`), and only after the user said yes in `LinkDialog`.
- Every new `.qml` file must be listed in `src/ui/CMakeLists.txt`; singletons also in `set_source_files_properties(... QT_QML_SINGLETON_TYPE TRUE)`. Never give a QML type the name of a Qt Quick / Controls type (`TabBar`, `Icon`, `TextMetrics` ...), and never a property the base type already has (`icon`, `text`, `font` on a Button): the build fails or the Qt type is used silently.
- UI texts: `Tr.s("key")` with both languages in `Tr.qml` (no `qsTr`); always `AppText` (not `Text`) so Thai and English have the same line height; icons are drawn by `LineIcon` (no icon font). Keep `objectName`s stable - `tst_ui_flow` uses them (`homeOpen`, `tab_<n>`, `tabClose_<n>`, `toolbarOpen`, `toggleSidebar`, `sidePanel`, `sideThumbs`, `sideOutline`, `sideComments`, `outline_<n>`, `comment_<n>`, `pageField`, `nextPage`, `prevPage`, `zoomIn`, `zoomOut`, `zoomLabel`, `fitWidth`, `fitPage`, `viewMode`, `rotate`, `darkPages`, `findButton`, `printButton`, `searchBar`, `searchField`, `searchCount`, `searchNext`, `searchPrev`, `searchCase`, `searchClose`, `linkUri`, `linkCancel`, `printDialog`, `printStart`, `printCancel`, `printRangeField`, `printError`, `langTh`, `langEn`, `passwordField`, `noticeBanner`, `recent_<n>`, `pageImage_<n>`, `pages`, `thumbnails`, `organizeButton`, `splitButton`, `homeMerge`, `organizerDialog`, `orgPage_<n>`, `orgDelete`, `orgUndo`, `orgSave`, `orgClose`, `orgResult`, `orgReplaceYes`, `orgDiscardYes`, `splitDialog`, `splitRangeField`, `splitStart`, `splitDone`, `compressButton`, `compressDialog`, `level_<name>`, `compressStart`, `compressSummary`, `compare_before`, `compare_after`, `compressSave`, `compressSaved`, `compressReplaceYes`, `compressClose`, `editButton`, `editBar`, `tool_<name>`, `editField`, `editUndo`, `editRedo`, `editDelete`, `editSave`, `editOpenResult`, `editClose`, `overlay_<n>`, `confirmYes`, `confirmCancel`, `formButton`, `formDialog`, `formField_<name>`, `formSave`, `formOpenResult`, `formClose`, `recoverAsk`).
- `tst_ui_flow` fails on any QML warning: run it after UI changes and fix every warning.
