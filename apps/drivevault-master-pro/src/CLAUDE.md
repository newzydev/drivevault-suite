# drivevault-master-pro/src - rules (adds to the parent files)

- `Hub` is a QObject exposed to QML as the singleton `Hub` (module `DriveVault.Master.Backend`). Its `Options` (registry root, data dir, app dir) exist so tests can use a fake registry key and temp folders - keep new state injectable that way; never read the real registry path directly elsewhere.
- Registry access only through `QSettings(NativeFormat)` below `HKEY_LOCAL_MACHINE` / `HKEY_CURRENT_USER`; read-only (the hub never writes product keys - installers own them).
- `WinUtil` is the only place with Win32 calls (`GetFileVersionInfo`, `ShellExecuteEx`). `runAndWait` uses ShellExecute so that installers whose manifest needs administrator rights prompt for it; it blocks, so call it from a worker thread only.
- Settings live in `<dataDir>\settings.ini` (language, user installer folders). No other persistence.
- Anything that starts a process must validate the file first (exists, `.exe`, DriveVault version resource). No shell command strings, no arguments from user text.
  **Exception for the AI (`src/ai/`, see the app `CLAUDE.md`)**: only `llama-server.exe` from the known engine folders, started with FIXED arguments (model path, a random port and key, thread count); the user's text goes in the HTTP body to it, never on a command line. The one other exception (owner's decision of 2026-11-16) is `CommandRunner` (tool `run_command`): it starts `cmd.exe /d /s /c "<command>"` in the working folder only after the user pressed Allow on that exact command in the card (every time, in every mode; never from a stored or earlier answer), without a window and without input, with a time limit, and kills it and its children on the limit or on Stop. The third (owner's decision of 2026-11-17, "like git") is `GitInfo`: it runs the `git` found on this PC (PATH or the Git for Windows folders) in the working folder of the agent page, READ ONLY, with fixed arguments only (`--no-optional-locks -c core.quotepath=false status --porcelain=v1 -b --untracked-files=normal`, then `diff --numstat HEAD`), no prompt, no index lock, output capped, killed after 10 s; no user text ever goes on its command line, and nothing that changes a repository (no add, commit, checkout, reset, push) may be added without a new decision. Nothing else may use these exceptions.
- `src/ai/` talks to the network only from `ModelDownloader` (a Download the user pressed), `AiService::probeLink` (a Check the user pressed, HEAD only) and `WebTools` (only when the switch "Web" is on and the local model asks for a search or a page: search words to DuckDuckGo, a GET of a public page; see the app `CLAUDE.md`). `HttpChat` and `LocalAgent` talk only to the local llama-server on this computer. `AgentTools` never leaves the chosen folder and has no tool that runs a program, deletes or uses the network (running a command is `CommandRunner`, asked every time). Keep conversations and settings in `<data>\ai\*.json`; never log a prompt or an answer.
- `Version.h` is generated from `CMakeLists.txt` (`project(... VERSION x.y.z)`); `app.rc` carries the same version by hand - change both together, and `AppVersion` comes from CMake in `package.ps1`.
- New code needs a test in `tests/tst_hub.cpp` (use `fake_setup.exe`, never a real installer).
