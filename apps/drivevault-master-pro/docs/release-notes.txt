DriveVault Master Pro - release notes
=====================================

v1.29.0 (2026-11-17): The AI can test a page at other screen sizes
  - New: the AI tool browser_viewport (mobile 390 x 844, tablet 820 x 1180, laptop 1366 x 768, desktop 1920 x 1080, or its own width and height; "reset" ends it). The page gets a window of exactly that size (media queries, menus of a phone, columns that stack), shown scaled to fit the browser pane with a bar that says which size it is (a cross ends the test); browser_read and browser_look then show the page at that size, and clicks, typing and drags still work. The AI is told to check a page at mobile / tablet / laptop and fix what breaks.
  - Fixed: the program could crash when it was closed after the browser had been used (the browser profile was destroyed before its pages).
  - Not code-signed (Windows SmartScreen may warn).

v1.28.0 (2026-11-17): The browser blocks nothing the engine can allow; downloads work
  - New: downloads. A file you start in the browser is saved in your Downloads folder (a name that never overwrites a file); the bar says so and has "Show in folder". Files that can run programs (exe, msi, bat, ps1, js, lnk ...) get a warning; the program never opens a downloaded file.
  - New: full screen for videos and pages (Esc leaves), copy / paste by pages, sound and video that start by themselves, screen sharing (you still answer the permission bar), the PDF viewer, and the browser no longer calls itself "QtWebEngine" (sign-in pages of some sites turned it away).
  - Fixed: the tabs used the default profile of Qt instead of the program's own (so downloads, the browser name and the saved cookies / permissions in `<data>browser` were not used). Cookies and permissions saved before are not carried over.
  - Still on purpose: a bad certificate stops the page, http content inside an https page is blocked, the AI cannot answer a permission question or click on a website.
  - Not code-signed (Windows SmartScreen may warn).

v1.27.5 (2026-11-17): Pages on this computer show their web fonts and styles in the browser

v1.18.0 (2026-11-17): A big file is written in parts, and you see what the AI is writing

A file that grows too long for one answer (more than about 14,000 characters) is stopped at once, the part that was written (up to its last complete line) is kept - you still answer Allow / Don't allow for it - and the AI goes on with the new tool "append_file", part by part, until the file is complete. Only when nothing can be kept is the AI asked again for something shorter; after three tries the job ends with a clear message.
  - New: a live line shows what is happening during the long waits: "Reading the conversation...", "Thinking...", "Writing the answer... (n characters)", "Writing index.html... (12,000 characters so far)", together with the clock. Before, the page said only "Starting..." for minutes.
  - New tool append_file: adds text at the end of a file (creates it when missing); every addition is shown on a card and needs your Allow like any change in "Ask first".
  - The context meter now shows the number the model server counted, from the stream of the answer.
  - Not code-signed (Windows SmartScreen may warn).

v1.17.0 (2026-11-17): The conversation is compacted like in Claude Code

A card in the conversation says "Conversation compacted - about 14,200 -> 640 tokens"; a click reads the summary.
  - Three ways: type /compact (optionally with a wish, e.g. /compact keep the file names), press "Compact now" in the Context part of the right panel, or let it happen by itself: before a message is sent, when the history that would go along has grown to three quarters of what is kept, the summary is written first and your message goes on after it. Stop ends a compaction.
  - Before, a long conversation lost its oldest messages without a trace. Now they are kept as a summary. Inside one long job the old results are still shortened or dropped to stay in the window, and the AI now keeps a short list of the steps that were dropped.
  - The token numbers on the card and in the panel are estimates (about 2.5 characters to a token) and say so; the meter shows the model server's own count of the last request when there is one. The summary is written by the small local model, so it can miss details - the card lets you read it.

    * a model on this PC: llama.cpp with a GGUF model. Download one of the catalogue (Qwen3.5 0.8B / 2B / 4B / 9B from Hugging Face) or paste a huggingface.co link to a .gguf file. Downloads start only when you press Download and are checked against a fixed size and SHA-256; Check on a pasted link only asks Hugging Face for its size and checksum. Everything stays on this computer.
    * an API: OpenAI style (OpenAI, OpenRouter, Ollama, LM Studio ...) or Anthropic, with your own key. The key is kept encrypted for your Windows user and is sent only to the address you set (https, or this computer).
    * Claude Code or Codex: the easy way - the program you already have and are signed in to. Master Pro starts it with fixed options and gives it the question on its standard input; it never sees your password. The agent page works in the folder you choose: read only, or "can edit files" if you allow it; it cannot run commands.
  - Answers stream in as they are written, can be stopped, and are kept as conversations (list on the left, saved in %LOCALAPPDATA%\DriveVault\MasterPro\ai). A failure is shown in the conversation in words, with what the service said.
  - Limits: Codex is tested with a stand-in only; a signed-in Claude Code session must be valid (the program says "Failed to authenticate" otherwise: sign in again with /login).
  - Not code-signed (Windows SmartScreen may warn).

v1.1.0 (2026-11-07)
  New
  - "Check for updates" button: asks the GitHub Releases of newzydev/drivevault-suite which version of each program exists. It runs only when you press the button;
    nothing is checked or downloaded in the background.
  - "Download version X and update / install": downloads the setup file from the official release address, compares its SHA-256 with the release's .sha256 file,
    checks that it is the right DriveVault program and version, then runs it like any other setup file. The downloaded file is deleted after a successful run.
  Changed
  - The licence text (EULA) says that "Check for updates" contacts GitHub.
  - Fixed: the Thai product section (6) of the licence text was shown garbled; the licence generator script is now saved with a byte order mark.
  Notes
  - (1.1.0 only) Master Pro did not update itself; since 1.2.0 it does.
  - GitHub limits anonymous requests (60 per hour per connection): if the check says so, try again later.

Known limitations
  - Installers are not code-signed (a certificate has to be bought). Windows may show "Windows protected your PC": choose "More info" and then "Run anyway".
    The SHA-256 check above protects against a damaged or swapped download, not against a compromised release.
  - Not tested on a clean machine / VM.
