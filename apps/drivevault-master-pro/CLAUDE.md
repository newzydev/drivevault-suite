# DriveVault Master Pro - rules (adds to the repository root file)

The hub of the suite: shows the installed DriveVault programs in their own accent colours, opens them, and installs / updates / uninstalls them from **setup files that exist on this PC**. Qt 6.8 / Qt Quick, C++20.
Every program installer installs this hub first (silently), so it is always present.

## Structure
```
src/        Hub (registry scan, installers, tasks, online update), Releases (GitHub release list parser, SHA-256 file parser), WinUtil (version resources, ShellExecute, version compare), main.cpp, app.rc
src/ai/     the AI (only the model on this PC): AiService / AiChannel (pages, conversations, model, effort, settings), HttpChat + Streams (streamed chat), LocalAgent + AgentTools + CommandRunner + WebTools (the agent loop, folder tools, commands, web tools), LlamaServer, ModelStore + ModelDownloader, ProcessUtil
qml/        Main, ProductCard, AboutDialog, AiWorkspace, AiSettingsDialog, TabSwitcher, MButton, MField, Theme (singleton), Tr (singleton: Thai / English table)
tests/      tst_hub, tst_ai (fake server on this computer), tst_window, fake_setup (test double for a setup / uninstall program)
installer/  master.iss + wizard pictures      scripts/  build, package, make-icon      docs/  notices, LGPL text
```

## Rules
- **Honest scope**: online access is limited to (1) the GitHub Releases list of `newzydev/drivevault-suite`, read when the user presses "Check for updates" and **once when the program opens** while the setting "Check for updates on start" is on (default on, `settings.ini` key `autoCheckUpdates`, a checkable item of the "..." menu in the top bar; the start check is quiet: it says nothing when it fails or finds nothing; it is off for `--screenshot` / `--list-products`), and (2) downloading one setup file from the official release address **only after the user presses an update button**. No automatic downloads, no repeated background polling, no online store. A download that still fails after the retries (HTTP 502/503/504, timeout) opens the release page (`html_url`, only below `Options::pagePrefix`) in the browser so the user can download by hand (`Hub::failOnline`, signal `releasePageOpened`); tests set `openPageOnFailure = false`. Master Pro can update itself (banner "Master Pro x.y.z is available" -> `Hub::updateSelf`: verified like any download, then run with its wizard: `Hub::setupArguments(true)` = `/NORESTART /CLOSEAPPLICATIONS /LANG=.. /UPDATE` + the scope; the setup closes Master Pro itself, shows the installing page and, after the user presses Finish, starts it again; an update of another program uses the same arguments - see `docs/suite-integration.md`, "Updating"). Image Editor Pro and Audio Editor Pro are listed as "Coming soon" because they do not exist. Do not add UI that implies otherwise.
- **Online update safety** (`Hub::downloadAndInstall`, `Releases.cpp`): download only from `Options::downloadPrefix` (official release URL); the `.exe.sha256` asset is mandatory and the SHA-256 must match; then CompanyName = DriveVault, ProductName = the catalog program and ProductVersion = the release version, otherwise the file is deleted and nothing runs. Release tags are `<apps folder name>-v<x.y.z>` (`drivevault-video-editor-pro`, `drivevault-image-editor-pro`, `drivevault-audio-editor-pro`; map in `slugForKey`); drafts / pre-releases are ignored. A new program that should get online updates needs its slug there. Tests use local files through `Options::releasesUrl` / `downloadPrefix`; the real exe never takes them from the command line. Signatures are still **not** verified - never call the SHA-256 check "signature verification"; it only catches a damaged or swapped download.
- **Tabs**: the top of the page has three tabs - Programs (`tab_programs`, the cards), AI Q&A (`tab_ask`) and Agentic AI (`tab_agent`). The last two are the same page, `qml/AiWorkspace.qml` (`mode` ask | agent), driven by the C++ objects `Ai.ask` / `Ai.agent` (`AiChannel`) of the QML singleton `Ai` (`AiService`, `src/ai/`); the tab switcher is `TabSwitcher.qml`. "Check for updates" (`checkUpdates`) sits at the right end of the search bar, which is only shown on the Programs tab.
- **AI (owner's decision of 2026-11-15, extends "Honest scope"; since 1.11.0 ONLY the model on this PC)**: both AI pages use llama.cpp's `llama-server.exe` with a GGUF file. The engine is found in `<app>\ai\llama` (shipped by the installer), `$DM_LLAMA_DIR`, the `ai\llama` folder of an installed program that ships it (PDF Pro) or the development `.tools\llm\llama-vulkan`; the model in `<data>\models`, `<app>\ai\models`, the `ai\models` of an installed program or the development `.tools\llm`. The server listens on 127.0.0.1 only, on a random port with a random key, and dies with Master Pro (Windows job object). There is NO API key, NO account, NO Claude Code / Codex and no other AI (removed on the owner's request: do not bring them back without a new decision). Network or process work happens **only when the user presses Send / Download / Check** (and, with the Web switch on, when the model asks for a search or a page); nothing at start-up.
- **Models** (`ModelStore`, `ModelDownloader`): the catalogue pins Qwen3.5 0.8B / 2B / 4B / 9B (Q4_K_M, unsloth GGUF, Apache-2.0) and Typhoon 2.5 Qwen3 4B (official Thai GGUF, not tested here) by commit, size and SHA-256 (values read from Hugging Face's headers on 2026-11-15; to add one, read `x-linked-size`, `x-linked-etag`, `x-repo-commit` of its `resolve` URL). A pasted link must be `https://huggingface.co/<owner>/<repo>/(blob|resolve)/<rev>/<file>.gguf`; "Check" does a HEAD request only; the download is pinned to the commit and verified against the size and SHA-256 Hugging Face reports; a file without a checksum is refused. The engine IS shipped: `ai\llama` (llama.cpp b12170 Vulkan, 22 files + the app-local C++ runtime), staged by `scripts\package.ps1` from `.tools\llm\llama-vulkan` and checked file by file against the audited SHA-256 list - the same list as PDF Pro: change both together. No model is shipped (the installer downloads one, see below). With no model chosen, `AiService::pickModelIfNone` takes an installed one (Qwen3.5 4B first).
- **Model and effort in the chat** (1.11.0): the message box has a model menu (`aiModel`, the installed models, "Manage models...") and an effort menu (`aiEffort`): `Effort::of` maps low / medium / high to `enable_thinking` (only "high": the model reasons first, about 3 times slower, announced as status `thinking`; the reasoning itself is never shown), `max_tokens` (2048 / 8192 / 12288), a safety cap of tool rounds (60 / 400 / 1000, see "Finishing a job") and how much history goes along. The server window is `LlamaServer::kContextTokens` = 32768 (`-c`, `--parallel 1`; PDF Pro has its own, smaller setting - do not assume they match). The effort is per page and saved; the chosen model is global.
- **Finishing a job** (1.14.0, `LocalAgent`): a job is not bounded by a number of rounds; it ends when the model has nothing left to do, the user presses Stop, or the model is stuck. The pieces that make that safe (each has a test in `tst_ai`): (1) the conversation is kept inside the window - older tool results and the text of old `write_file` / `edit_file` calls are shortened, then the oldest steps dropped (a call with its results together; the system message and the user's task stay), the activity line says "Made room"; a server answer "does not fit" shortens harder and asks again (3 times at most); (2) an answer cut by `max_tokens` goes on (`finish_reason` length, 8 times at most) and one cut inside a tool call (HTTP 500 "tool call") is asked again for a shorter one (twice); (3) a silent answer is asked again (3 times); (4) an answer while the task list (`todo_write`) still has open items is not accepted: the model is asked to finish or close the list (3 times); (5) the same file / command call 3 times in a row is refused with a hint, the 8th ends the job with `stuck`; the same web call twice or more than 4 web calls are refused; (6) `read_file` returns about 600 lines at a time (`start_line` / `max_lines`). Every one of these shows an activity line - nothing is done silently. The messages carry `startedMs`, `durationMs` and `steps` (the page shows a running clock and "Took m:ss"). `maxSteps` stays as a last safety net.
- **Local agent and web** (owner's decision of 2026-11-15; extended by the owner on 2026-11-16 to work like Claude Code: edit_file, glob, task list, plan approval, commands, slash commands): the Agentic AI page runs `LocalAgent` (a tool-calling loop against llama-server, `chat/completions` with `tools`, at most `Effort::maxSteps` rounds) over `AgentTools` (`list_files`, `read_file`, `search_text`, `glob_files`, and `edit_file` (one exact, unique piece of text replaced; `replace_all` for every one) / `write_file` only in the modes below): every path is relative to the chosen folder and may not leave it (no `..`, drive, `:` stream or link outside; tested), a changed file is copied to `<folder>\.drivevault-backup` first, no file tool deletes, renames or uses the network. Besides the file tools `LocalAgent` handles `todo_write` (the task list the page shows in the right panel; `AiChannel::todos`), `exit_plan_mode` (plan mode only) and `run_command` (see "Commands" below). `LocalAgent` also refuses the same web call twice and allows at most 4 web calls per task (a small model searched 12 times in a row). `WebTools` (`web_search` via `https://html.duckduckgo.com/html/`, `fetch_page`) is offered on both pages when the setting `web` is on (default on, `Ai.webEnabled`, chip "Web" under the message box, switch in the AI settings): it opens only http(s) on a PUBLIC address (`WebTools::checkUrl` + a DNS check of every answer, again after every redirect; no user info, only ports 80 / 443; 600 KB / 12000 characters at most). A Q&A request with web on goes through `LocalAgent` without a folder; with web off it is a plain streamed chat (`HttpChat`).
- **Modes of the agent** (1.12.0, `AiChannel::permission`, saved per page, menu `aiMode`, Shift+Tab cycles ask > edit > plan > read, `/mode`): `read` (look and answer; no change tools, no commands), `plan` (the read tools + `exit_plan_mode`: the model explores, then calls it with a plan; `LocalAgent::planApprovalNeeded` -> the card `aiApproval` (kind `plan`) shows the plan with "Approve and start" / "Keep planning"; approved -> `planApproved`: the running agent gets edit tools and commands, `approveWrites` on, and the page switches to `ask`; not approved -> the model is told to revise; nothing can change before the approval), `ask` (the default: `write_file` / `edit_file` are offered but every call WAITS: `LocalAgent::approvalNeeded` -> the card shows the path and a preview (a red / green diff for `edit_file`) with Allow / Don't allow -> `AiChannel::answerApproval` -> `LocalAgent::answerApproval`; nothing is written and the model is not asked again until the answer; "don't allow" tells the model so; Stop ends the wait) and `edit` (file changes without asking; the old file is still copied to `.drivevault-backup`). **Commands**: `run_command` is offered in `ask` and `edit` only, and EVERY command waits for the user in both (card kind `command`: the command text and the warning that it runs on the PC with the user's permissions and is not limited to the folder; `CommandRunner`: `cmd.exe /d /s /c` in the working folder, no window, no input, output of both streams cut to 8000 characters with the exit code, 60 s default / 300 s at most limit, killed with everything it started on the limit or on Stop). This replaces the owner's earlier "no tool that runs a program" rule (2026-11-15) by the owner's decision of 2026-11-16; keep the ask-every-time rule and never add a tool that deletes outside the job or reaches the network on its own. An older settings file with `allowEdits` becomes `edit` (true) or `ask`.
- **Slash commands and folder instructions** (2026-11-16, `AiChannel::slashCommand`, handled before the model is asked, answers are local messages): `/help`, `/clear` (`/new`), `/effort`, `/web` on both pages; `/mode`, `/todos`, `/init` (sends a prompt that makes the model write CLAUDE.md) on the agent page; Esc stops the work. When the working folder has a `CLAUDE.md` (else `AGENTS.md`) its first 6000 characters go into the system prompt and the activity line says so. Context compaction (`/compact`) does not exist: do not label anything that way.
- **The installer downloads the model** (`installer\windows\master.iss`, task `aimodels`, on by default, the same Inno code as PDF Pro): Qwen3.5-4B Q4_K_M from the pinned Hugging Face revision, SHA-256 checked by the download itself, into `{app}\ai\models`; silent installs never download; a failure installs the program anyway and says so. The constants (URL, size, SHA-256) must equal `ModelStore::catalog()` "qwen35-4b" and PDF Pro's: change them together.
- **Honest AI pages**: a message is never answered by anything but the local model; every failure is shown in the conversation (`errorCode` + `errorDetail`, texts `err_*` / `why_*` in `Tr.qml`); the page says what is missing (`AiChannel::notReady`: noEngine / noModel / noFolder) instead of looking ready.
- **Only DriveVault setup files are started** (version resource `CompanyName = DriveVault`). Signatures are **not** verified - never describe that as verification. Master Pro's own setup is offered only through its own banner (`selfUpdateVersion`), never as a program card.
- Programs are found through `Software\DriveVault\Products\<Key>` in HKLM and HKCU (contract: `docs/suite-integration.md`). Catalog keys: `VideoEditorPro`, `ImageEditorPro`, `AudioEditorPro`; unknown keys are listed generically.
  A registry entry whose program file is gone is "broken" (Needs repair), never "installed".
- Long work (running a setup / uninstaller) runs on a worker thread, one task at a time (`Hub::busy`); the UI must never block. Exit codes are shown, not hidden. Network work (`QNetworkAccessManager`, async, 30 s inactivity timeout) runs on the main thread and sets `Hub::checking` or `busy` while it works.
- Texts: every user-visible string is in `qml/Tr.qml` (Thai + English) or `Hub::tr2(en, th)`. Add both languages together.
- UI: neutral dark surfaces + one accent per program (`product.accent`); Inter + Noto Sans Thai. Controls have `objectName`s that the tests use (`launch_<key>`, `install_<key>`, ...).
- QML gotchas: ids of one file are not visible in another file (use signals); QVariantMap values that are empty strings must be `toString()`-ed or QML sees `undefined`.

## Commands
```powershell
.\scripts\build.ps1 -Test        # build + tst_hub + tst_window
.\scripts\package.ps1            # + windeployqt, app-local VC runtime, dependency check, license-file checks, Inno Setup -> dist\DriveVault-Master-Pro-Setup-x64.exe
```
Diagnostics of the exe: `--list-products <file.json>`, `--screenshot <png> [--size WxH] [--lang th|en] [--tab programs|ask|agent] [--ai-view settings|model|effort]`, `--registry-root <key>`, `--data-dir <dir>`.
The real local model is tested only on request: `DM_TEST_REAL_LLM=1 build\release\bin\tst_ai.exe realLocalModelAnswers realLocalPage` (loads the 2.7 GB model from `.tools\llm`; about 10 s on the development PC).

## Installer behaviour that must stay true (tested by the Video Editor `test-installer.ps1`, which only the owner runs)
Installs to `C:\Program Files\DriveVault` (admin) or per-user; creates `installers` and `Common`; registers `Software\DriveVault\MasterPro`; **refuses to uninstall while any program is installed** (also silently);
after uninstalling it removes the empty suite folder (delayed `rmdir`, only empty folders). Version resource: ProductName `DriveVault Master Pro`, CompanyName `DriveVault`.
