# drivevault-master-pro/installer - rules (adds to the parent files)

- `windows/master.iss` is built by `scripts\package.ps1` (passes `AppVersion`, `StageDir`, `OutputDir`). Wizard pictures are generated by `shared\scripts\make-brand-assets.ps1 -Accent "#F59E0B" -Title "Master Pro"`; the icon by `scripts\make-icon.ps1`.
- `AppId` is permanent. The install folder is fixed (`DisableDirPage=yes`); only the command line `/DIR` changes it. Default dir `{autopf}\DriveVault`, `PrivilegesRequired=admin` with `dialog commandline` overrides (program installers pass `/ALLUSERS` or `/CURRENTUSER` plus `/DIR`).
- **Updating** (owner's request 2026-11-16; contract in `docs/suite-integration.md`, "Updating"): `CloseApplications=force` (Setup closes the running program itself), `IsUpdate()` = `/UPDATE` or an existing uninstall key of this `AppId` (the GUID in `UninstallKey` must equal `AppId`), `ShouldSkipPage` skips welcome / licence / components / tasks / ready for an update, and the Finish page's "Launch" entry (`postinstall`, ticked) opens the program again. The hub starts it with `Hub::setupArguments`. Do not turn the launch into a silent relaunch and do not make updates download the model. Keep the three installers (Master Pro, Video Editor, PDF Pro) in step.
- Keep `InitializeUninstall` refusing while any `Software\DriveVault\Products\*` key exists (HKLM and HKCU, 64 and 32 bit views).
- The delayed `rmdir` after uninstall may only remove **empty** folders (`Common`, then the suite folder).
- After changing the script: rebuild this installer first, then the Video Editor installer (it embeds this one), and smoke start the program. Do not run the Video Editor `test-installer.ps1` or install / uninstall anything - the owner runs it when wanted.
