# drivevault-video-editor-pro/installer - rules (adds to the parent files)

- `windows/drivevault.iss` is compiled by `scripts\package.ps1` with `AppVersion`, `StageDir` and `OutputDir`. Do not run `iscc` by hand without these defines.
- Install location: `{autopf}\DriveVault\Common\DriveVault Video Editor Pro` (admin default; `dialog commandline` overrides the scope). The folder is **fixed**: `DisableDirPage=yes`, only the command line `/DIR` changes it (tests). `SuiteDir` (Pascal) = parent of the `Common` folder = where Master Pro lives.
- **Master Pro is not inside this installer** (owner's request 2026-11-19): `PrepareToInstall` (shared code `shared\installer\master-hub-code.iss`, messages in `master-hub-messages.iss`, the same include in `pdf.iss`) asks the GitHub releases API for the newest `drivevault-master-pro-v<x.y.z>` (not a draft / pre-release, both `DriveVault-Master-Pro-Setup-x64.exe` and `.sha256` present), downloads the setup with its SHA-256 checked (`DownloadTemporaryFile`, retried with growing pauses) and runs it silently with the same scope switch and language as this setup - when Master Pro is missing or older (HKLM or HKCU). Best effort: offline or any failure never stops the program from being installed; `MasterNote` says so on the last page; an installed Master Pro is kept when GitHub is not reachable; `/NOMASTER` skips the step. Tested with a throw-away installer that only runs this code (real GitHub: newest tag found, download and SHA-256 check, a wrong checksum refused, a dead address gives up with an error); the shared code is plain Pascal - change it in one place. `test-installer.ps1` (owner only) now needs the Internet: it installs the newest PUBLISHED Master Pro.
- Registry for the hub (`Software\DriveVault\Products\VideoEditorPro` incl. `Uninstaller`), the `.dvproj` association (component `assoc`), Start Menu folder `DriveVault`, optional desktop icon. The uninstaller never deletes projects and asks before deleting settings / cache; it must not remove other DriveVault programs or Master Pro.
- `AppId` `{6E1B7A52-4C3D-4F7E-9A3B-D17E5A0C2F11}` never changes. Wizard pictures: `shared\scripts\make-brand-assets.ps1` (accent `#8B5CF6`).
- **AI models are downloaded by the wizard, not shipped** (the OpenThai model is 2.6 GB; a GitHub release file is limited to 2 GB): task `aimodels` (on by default) on the Ready page -> `DownloadModels` (Inno `TDownloadWizardPage`, SHA-256 per file, pinned revisions: OpenThai fp32 + Whisper tiny and small; the same values as `src\ai\OpenThaiInstaller.cpp` - change both together) into `{tmp}`, then `PlaceModels` after the files are installed (`{app}\ai\openthai` incl. `LICENSE` and the unpacked zip via Windows `tar.exe`, `{app}\ai\models`). Silent installs never download. A failure, a cancel or too little disk space installs the program without the models and says so (`ModelsNote`). `[UninstallDelete]` removes them. Whisper base is still inside the installer.
- **Updating** (contract in `docs/suite-integration.md`, "Updating"; same code in `pdf.iss` and `master.iss`): `CloseApplications=force`, `IsUpdate()` (`/UPDATE` or an existing uninstall key; the GUID in `UninstallKey` must equal `AppId`), `ShouldSkipPage` (welcome, licence, components, tasks, ready are skipped for an update), the ticked "Launch" entry reopens the program after Finish, and when `/UPDATE` was given and this setup replaced Master Pro (`HubReplaced`), the hub is opened again after Finish (`ExecAsOriginalUser`). Silent installs never relaunch.
- After a change here rebuild with `scripts\package.ps1` (Master Pro first if its installer changed) and smoke start the program. Do not run `scripts\test-installer.ps1` or install / uninstall anything - the owner runs it when wanted.
