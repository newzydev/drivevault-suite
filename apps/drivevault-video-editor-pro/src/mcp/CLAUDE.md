# src/mcp - rules (adds to the parent files)

- `McpServer` is a Model Context Protocol server (Streamable HTTP, JSON-RPC 2.0, protocol 2025-06-18 / 2025-03-26 / 2024-11-05) inside the running program, so Claude Code, Codex or any MCP client can work on the **open project**. It is **off by default** (`mcpEnabled`), listens on **127.0.0.1 only** (`mcpPort`, default 38491) and every request needs `Authorization: Bearer <mcpToken>` (constant-time compare; the token is created on first start, `regenerateToken()` cuts the old one off at once). Requests with an `Origin` header (a browser page) are refused with 403.
- Tools run on the **UI thread** through the same models as the UI (`ProjectManager`, `TimelineModel`, `AiController`), so every edit is one undo step and appears on the timeline at once. Long work (silence search, transcription) only *starts* in the tool and the client polls `get_ai_status`; `apply_*` is the separate confirmation step, as in the UI.
- Safety rules for tools: no shell, no process start, no file deletion, no network; paths from a client must be absolute and exist (`import_media`, `open_project` only accept an existing media file / `.dvproj`); a tool that would replace the open project refuses while it has unsaved changes unless the client passes `discard_unsaved: true`; text from a client is never passed to a process.
- A new tool: `addTool(name, description, properties, required, readOnly, lambda)` in `registerTools()`; read arguments through `Args` (it reports missing / wrongly typed ones, never guesses); return `""`-style results as `textResult` / `jsonResult`, errors as `fail(...)`. Add it to the expected list in `tests/unit/tst_mcp.cpp` and test it on real media with undo. Keep tool names stable: clients and user prompts depend on them.
- The AI cursor: `onReadyRead` calls `announce(tool, args)` for every `tools/call` (setting `mcpCursor`), which emits `agentAction(target, label, frame, trackRow)` for `Main.qml` / `AgentCursor.qml`, and a tool that changes something is run after a short delay (700 ms) so the pointer arrives first; `handleMessage` itself stays synchronous (tests). A new tool needs a branch in `announce` (label with `tr`, target) or it gets the "Reading the project" caption.
- Not exposed (do not claim otherwise): export / render, effects and keyframes, tracking, enhancement, titles other than subtitles.
- `tests/unit/tst_mcp.cpp` covers the protocol (initialize, version negotiation, errors, notifications), the tools on a real project (import, add, split, undo / redo, delete, subtitles, project guards), the AI switch and the HTTP layer over a real socket (token, Origin, path, method, token rotation, port closed when switched off).
