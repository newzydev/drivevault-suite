# src/ai - rules (adds to the parent files)

- AI is an **optional module** on top of the editing core: nothing in `timeline`, `playback` or `export` may depend on it. Everything runs offline on this PC; nothing is uploaded.
- Analyses (silence, scenes, captions, tracking, enhancement) only produce results; **applying them is a separate user-confirmed call** (`apply*`) and is one undo step. Never edit the project from an analysis.
- Labels are honest: enhancement is classical spectral noise reduction (not a neural model); the assistant is a deterministic keyword parser (Thai + English) producing typed commands - not a language model; tracking is template matching. Captions can be wrong; say so in the UI.
- whisper.cpp runs as a **separate process** (`whisper-cli.exe`, found via `whisperExecutable()`: `<app>\ai\whisper`, `DV_WHISPER_DIR`, or the suite `.tools`). Progress is parsed from its output; cancel kills it. Speech models (ggml) are not bundled: the user downloads (explicit click, Hugging Face) or imports them; `ModelManager` validates imports (magic + size).
- **Edit by prompt** (`EditPlanner.cpp`, `AiController::planEdit / applyEditPrompt`) is the same kind of thing: a deterministic Thai / English keyword planner (catalogs of looks, effects, transitions, text styles with aliases; numbers must match the tiles of `ToolPanel.qml` and the `addTitle` table), never a language model. It only calls timeline / project operations, runs as ONE undo macro, lists what it did not understand and never guesses; the export step is started by the UI (never overwrites a file). A new catalog entry needs its aliases, a label (`QT_TRANSLATE_NOOP("EditPlanner", ...)`) and a test in `tst_ai.cpp`.
- **Language model** (`LocalLlm`): Qwen3.5 4B (Apache 2.0, GGUF) run by llama.cpp's `llama-server` (MIT) as a separate process on 127.0.0.1 (random port, one slot, no web page, model path never from user text). It is only a translator from a free sentence to the planner's steps: the answer is forced into JSON by a grammar (`llmSchema`) and re-validated by `planFromLlmJson` (catalog names, number ranges) before anything can run; the user sees the plan first. The model file is downloaded only by a button (size + SHA-256 checked, never overwritten silently); the server starts on the first request and stops after 10 idle minutes and at exit. Without the model, engine or setting (`aiUseLanguageModel`) everything works through the keyword planner.
- The assistant may only call the services in `AiController`; no shell commands, no file access outside the project, no text from the user passed to a process.
- One AI task at a time (`AiController::busy`), on a worker thread, with progress and cancel.
- Tests in `tests/unit/tst_ai.cpp` use real data: generated audio / video, the Windows speech synthesiser -> real whisper + model (skipped only when whisper or a model is absent).
